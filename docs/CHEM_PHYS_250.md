A plan for 250 original Chemical and Physical Foundations questions in ten batches of 25, each batch a mini section: four passages (190 questions in all, ten passages of four questions and thirty of five) plus six standalone questions, mixing physics, general chemistry, biochemistry and organic chemistry. Every question has a permanent id (CP-001 to CP-250; passages CP-P01 to CP-P40) assigned here, before writing, so progress saved on a phone never breaks. Writing follows MCAT_SPEC §3: every experiment hypothetical and labelled, every fact verified against a named source, every number re-derived, every item fact-checked by a second pass, and every batch gated by an independent blind re-solve (a fresh session re-solves every item from the blind packet) before it is committed or pushed; items are `draft` until they pass.

## 2. How the plan is used

- **Files.** One block file per batch, `content/mcat/chem_phys/batch_01.json` … `batch_10.json` (block ids `CP1`–`CP10`); passages keep the ids below (`CP-P01` …) and questions keep `CP-001` …. `tools/validate.py` accepts these files (batch N must hold exactly the ids assigned to it here: 25 questions and 4 passages per batch) alongside the `M<n>` blocks. Each batch also gets a numbers-check script and a review packet: `review/chem_phys_batch_NN_check.py` (every number re-derived, structures checked with RDKit) and `review/chem_phys_batch_NN.md` (generated by `py tools/review_packet.py <block.json> <packet.md>`).
- **Order.** Batches are written in order, one per session: write → fact-check (every number re-derived in the batch's check script, every citation fetched, originality search) → fixes → `py tools/validate.py`, `py build.py`, the three tests → MCAT_SPEC §10 and §11 → **independent blind re-solve** in a fresh session (`review/chem_phys_batch_NN_blind.md`, compared against `review/chem_phys_batch_NN.md`) → fixes and re-solve of any item that failed → `status: reviewed`, `reviewed_by: "independent blind re-solve"` → commit `Add Chem/Phys batch N (CP-xxx to CP-yyy)` → push. Nothing is committed or pushed before the batch passes.
- **Status.** Each batch header and each question carries a status: `planned` → `written` → `checked` (fact-check applied) → `reviewed` (passed the independent blind re-solve) → `pushed`. The owner does not review in the app. Update them as each step completes and add a changelog line (§5).
- **Figures.** Every figure is drawn from data stored with the passage (tables, line and bar charts, KaTeX equations, RDKit structures from SMILES), per MCAT_SPEC §5 and §8; the figure types below are commitments, not suggestions.
- **Settings never repeat.** Each of the forty settings is used once. A batch that needs a replacement passage takes a setting not in this list and records it here.
- **Existing items.** Blocks M1, M4 and M4B already hold 23 Chem/Phys questions; the plan does not count them and avoids their specific scenarios (battery internal resistance, the 4B fluids set).
